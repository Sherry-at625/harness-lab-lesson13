# 指标口径（metrics_spec.md）

> 运营周会 / 财务对账共用口径。**先定口径，再算数字**；口径写不清，数字就是猜。

## 0. 三个集合，先定义清楚

| 集合 | 定义 | 符号 |
|---|---|---|
| 校验后订单全集 | 通过 cleaning_spec 全部校验、去重后的订单（**含退款订单**） | O |
| 退款订单 | O 中 `refund_flag = 1` 的订单（以 orders 表为准） | R |
| 净销售订单 | O − R | E |

## 1. 核心指标

| 指标 | 公式 | 单位 | 说明 |
|---|---|---|---|
| GMV | Σ `amount`（仅 E） | 元 | **不扣退款**，退款另算；只统计净销售订单 |
| 有效订单数 | `count(distinct order_id)`（仅 E） | 单 | |
| 客单价 AOV | GMV ÷ 有效订单数 | 元/单 | 分母是订单数，不是行数 |
| 退款订单数 | `count(distinct order_id)`（仅 R） | 单 | |
| 退款率 | 退款订单数 ÷ `count(distinct order_id)`（O） | % | **分母是 O，不是 E** |
| 退款金额 | Σ `refund_amount`（清洗后 refunds） | 元 | 超额退款已剔除 |
| 毛利额 | Σ (`amount` − `qty` × `cost_price`)（仅 E） | 元 | 成本取主数据 |
| 毛利率 | 毛利额 ÷ GMV | % | |

## 2. 分组维度

- `by_store`：按 `store_id` 汇总 GMV、有效订单数、AOV
- `by_category`：按 `category`（主数据标准类目）汇总 GMV、销量 `qty`
- `weekly_gmv`：按 `week`（W01~W13）汇总 GMV（仅 E）

## 3. 精度与格式

- 金额保留 2 位小数；比率保留 4 位小数（如 `0.0617`，不要写 `6.17%`）
- `metrics.json` 中整数用 int，金额用 float
- 验收容差：金额 ±0.5%，订单数必须完全一致

## 4. 常见口径错误（会被对账打回）

1. 退款订单也计入 GMV → GMV 虚高（本次约高 2000+ 元）
2. 退款率分母用 E → 退款率偏高约 6%
3. 用订单行数当订单数 → 客单价偏低约 40%
4. 毛利率用 `discount` 当成本 → 毛利率虚高 15 个百分点以上
5. 把 6 月试运行数据算进来 → 期间外数据污染趋势
